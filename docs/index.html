Static onboarding pages

Turn walkthrough artifacts into polished user docs.

The rs-onboarding-pages-docs skill helps convert screenshots, rollout notes, and implementation evidence into simple HTML pages that read like onboarding guides instead of internal delivery notes.

See the workflow Setup guide

Who this is for

Teams that already have screenshots, notes, and examples, but want the final site to feel like a clean product walkthrough for new users.

End-user onboarding Static HTML GitHub-friendly docs

What it produces

A lightweight docs site centered on docs/index.html, with clear steps, helpful screenshots, and outcome-focused copy. 

docs/
├── index.html
└── assets/
    └── images/

How it works

  1. Start from the user journey you want to explain.
  2. Collect the screenshots, notes, and visible outcomes that support that journey.
  3. Rewrite internal evidence into user-facing steps and expectations.
  4. Publish the result as a static page with a clear landing experience.

Writing rules

  • Lead with what the user can do.
  • Show the main action before edge cases.
  • Use screenshots to clarify visible states.
  • Keep the copy outcome-focused and concise.

Avoid this

  • Internal QA phrasing
  • Engineering changelog voice
  • Proof-of-work or agent narration
  • Product-specific confidential examples in shared skill guidance

Install the skill

Add the skill from this repository, then invoke it when you need to turn implementation artifacts into onboarding-ready docs. 

skg psm8/ai -s rs-onboarding-pages-docs

Use it when you have

  • feature walkthrough screenshots
  • release or rollout notes
  • manual verification notes that need rewriting
  • a repo that should publish static docs without a full site generator

For installation details and the broader repository setup, see docs/setup.md.
